Tasks need people. Every task occupies one worker for its whole duration, and
a team only has so many.

- `schedule(workers) -> list[list]` — schedule the project with at most
  `workers` tasks running at once, and return `[name, start, finish]` for every
  task, ordered by start day, then by name. Raises `ValueError` if
  `workers < 1`.

Schedule day by day with this rule. A task is *ready* on a day when it has not
started and all of its dependencies have finished on or before that day. While
a worker is free and a task is ready, start the ready task with the longest
*tail* — its own duration plus the longest tail among the tasks that depend
on it — breaking ties by name. Then move to the next day on which a running
task finishes.

The tail is the length of the longest chain from the task to the end of the
project, so the rule starts the work that most holds up the finish first.

`schedule` is a what-if: it does not change `start`, `finish`, `length`,
`slack` or `critical`, which still assume unlimited workers.
