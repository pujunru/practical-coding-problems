Orders now take stock, and stock can run out.

- `OrderService(stock)` — `stock` maps an item to the units on hand. An item
  that is not in the map has `0`. Without the argument, stock is unlimited as
  in Level 1.
- `place_order` takes `quantity` units of `item`. If there are not enough, the
  order is rejected: nothing is taken, no order is created, and the call
  returns `"rejected"`.
- `get_stock(item) -> int` — units on hand.
- `restock(item, quantity)` — add units.

**Read, check, then process.** Handle a request in this order:

1. **Read**: look the key up.
2. **Check**: if the key has a result already, return it and stop.
3. **Process**: check stock, take it or reject, and **record the outcome under
   the key**.

The outcome is recorded whether the order was placed or rejected. A retry of a
rejected request returns `"rejected"` again, even if stock has arrived since:
the client asked once and got one answer. A new attempt needs a new key.

### Review checklist

- A retry never takes stock a second time.
- The stock check and the deduction happen only on the first call.
- Rejections are recorded too, so a retry gives the same answer.
- Nothing is changed when an order is rejected.
