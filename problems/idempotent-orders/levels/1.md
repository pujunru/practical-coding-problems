A shop's checkout calls an order service over a flaky network. When a request
times out, the client cannot tell whether the order was created, so it sends
the same request again. Today every retry creates another order, and customers
get charged twice.

The fix is an **idempotency key**. The client generates one key per checkout
and sends it with every attempt. The server creates the order the first time
it sees the key and answers every later attempt with the same result.

Implement the `OrderService` class:

- `OrderService()` — an empty service.
- `place_order(user_id, key, item, quantity) -> str` — place an order and
  return its id. Ids are `"order-1"`, `"order-2"`, … in the order they are
  created.
- `order_count() -> int` — how many orders have actually been created.

**The rule.** The first call with a given `key` creates an order. Any later
call with the same `key` creates nothing and returns the id from the first
call.

In this level stock is unlimited, and every key belongs to a single user and
a single request.

### Review checklist

- The key is looked up **before** any work is done.
- A retry is answered from what was stored, not by doing the work again.
- A retry does not use up an order id.
